# TeaseScript AI shared project context

Start here when a new connector-local agent has no prior project context. This
project folder provides stable routing, trusted local tooling, and separate
research context. It is not the source of truth for current implementation,
accepted syntax, ADRs, or runtime behavior.

## Reading and startup route

1. Read the complete project-instruction section later in this combined `README-FIRST.md` for stable product and architecture boundaries.
2. Read the complete development-workflow-context section later in this combined `README-FIRST.md` for the applicable GitHub and publication route.
3. For substantial Linux x86_64 implementation, review, debugging, or verification, read the complete local-agent-bootstrap section later in this combined `README-FIRST.md` and use the standalone `setup-chatgpt-project-agent.sh` when the installed environment is absent or must be refreshed.
4. In the verified local checkout, read applicable `AGENTS.md` files first, then the repository's `README-FIRST.md`, assigned issue or pull request, and only the controlling task documents and ADRs.

When the trusted local environment is present, do not start with network Git,
repeated connector file reads, or the candidate repository copy of the source
preparation helper. The connector is the GitHub control plane; local shell and
the installed environment are the repository inspection and execution route.

Use the complete Codex model-selection section later in this combined
`README-FIRST.md` only when selecting a Codex model or writing a Codex execution
prompt. Use `TeaseScript-AI-Research-Archive.zip` only for explicitly
non-authoritative capability or historical research.

## Source of truth

The GitHub repository `TeaseScript-AI/teasescript-platform` owns:

- current implementation and tests;
- exact architecture and implementation status;
- accepted specifications and ADRs;
- current topic documents and unresolved decisions;
- active planning and `WISHES.xml`;
- executable tested examples and repository workflow.

Do not infer current implementation from an older shared-project file, audit,
research archive, or repository snapshot.

## Stable project files

Keep one current unsuffixed copy of each project file:

```text
README-FIRST.md
chatgpt-project-agent-tools-linux-x64.tar.gz
chatgpt-project-agent-runtime-linux-x64.tar.zst
setup-chatgpt-project-agent.sh
TeaseScript-AI-Research-Archive.zip
```

`README-FIRST.md` is generated by concatenating the complete configured source
files in a fixed order. Those source files are not uploaded separately. The
small tools archive is made externally from GitHub's
`tools/chatgpt-project-agent/` directory. Internal release identity belongs in
archive metadata, not in versioned or suffixed project filenames.

Before installing a replacement set, remove older copies that the project UI
renamed with suffixes such as `(1)` or `(2)`. Do not overlay or manually merge
generated project files. A repository merge does not prove the project folder
was updated; record the manual replacement separately.

## Local execution tool

Use the direct shell/container facility for extraction, filesystem inspection,
Git, Bash, Node, npm, and Python. Python execution remains appropriate when the
task is the installed repository-owned Python helper itself.

A generic client/service error before command output starts is not proof of
archive corruption. Retry a minimal direct-shell check and report the actual
failing layer.
