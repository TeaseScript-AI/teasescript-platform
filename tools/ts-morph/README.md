# Agent-safe TypeScript codemods

These repository-owned tools use ts-morph for bounded, symbol-aware TypeScript changes. They are development tools only. They do not run in the engine, player, Standard Library, package libraries, build output, or published runtime APIs.

Use an ordinary checked patch for a small local edit. Use a codemod when the same semantic change must update declarations, imports, re-exports, or references across several TypeScript files. Do not use these tools for `.tease` files.

## Rename one top-level symbol

Run from the repository root:

```bash
npm run codemod:rename-symbol -- \
  --check \
  --file src/example.ts \
  --old oldName \
  --new newName
```

`--check` performs the complete rename in memory, prints stable JSON containing the exact changed-file set, writes nothing, and exits with status 1 when changes are required. Replace `--check` with `--write` to save those files. A repeated `--write` is an explicit no-op when the target already contains exactly one supported declaration under the new name.

The target must be one repository-relative TypeScript file included by `tsconfig.json`. Supported top-level declarations are functions, classes, interfaces, type aliases, enums, and identifier variable declarations. The tool refuses missing or ambiguous targets, an existing destination declaration, invalid identifiers, generated `.d.ts` targets, symlinks, and paths outside the repository.

The shared ts-morph project fixes two-space indentation, LF newlines, double quotes, and trailing commas for nodes generated by present or future codemods. Reference-aware rename normally changes only identifier text and preserves unrelated layout, but every resulting diff still requires review.

After any write:

```bash
npm run check
git diff --check
git diff --stat
git diff
```

TypeScript 7 remains the authoritative build and typecheck. ts-morph currently uses the repository's TypeScript 6-compatible tooling API and must not replace the normal compiler checks.
